## 1. 系统/方法概述

该仓库是一个基于 React + Vite 的 Figma UI 静态站点，不包含后端服务、API 层或服务器端错误处理。错误处理完全发生在浏览器端，采用以下轻量级策略：
- 组件内部状态管理资源加载失败（如图片加载失败）
- 使用 `throw new Error(...)` 在 Hook 被误用时快速失败
- 通过 `sonner` 的 `toast.error/success/info` 向用户反馈表单校验与操作结果
- 对异步导出等操作使用 `try/catch` 捕获并 `console.error` 记录
- 无全局错误边界、无自定义错误类型、无 panic/recover 机制

## 2. 关键文件与位置

- **资源加载错误**：`figma-ui/src/app/components/figma/ImageWithFallback.tsx` — 监听 `onError`，切换为内联 SVG 占位图
- **Hook 使用约束**：`figma-ui/src/app/components/LaunchNoticeProvider.tsx` 中 `useLaunchNotice` 在未 Provider 包裹时抛错；同目录下 `carousel.tsx`、`chart.tsx`、`sidebar.tsx` 等 UI 组件的 Hook 也采用相同模式
- **表单错误展示**：`figma-ui/src/app/components/ui/form.tsx` — `FormMessage` 读取上下文中的 `error` 字段并以 `text-destructive` 样式渲染消息
- **用户输入校验**：`figma-ui/src/app/pages/Login.tsx` — 手机号长度校验失败时调用 `toast.error("请输入正确的手机号")`
- **异步操作异常**：`figma-ui/src/app/pages/LogoPage.tsx`、`PromoPage.tsx` — 使用 `try/catch` 捕获导出异常并通过 `console.error` 记录

## 3. 架构与约定

- **无统一错误类型定义**：项目未定义自定义 Error 子类或错误码枚举，所有业务错误以字符串形式直接抛出或通过 toast 提示。
- **组件级错误隔离**：每个可失败的 UI 片段自行处理其错误状态（如 `ImageWithFallback` 用 `useState(false)` 标记 `didError`），不向上冒泡。
- **Hook 契约通过运行时断言保障**：需要 Context 的 Hook 在 context 为空时立即 `throw new Error(...)`，强制调用方正确包裹 Provider。
- **用户可见错误走 toast**：表单校验、登录成功/失败等用户交互反馈统一通过 `sonner` 的 toast API，而非 alert 或页面内文本。
- **不可恢复的错误走 console**：导出失败等调试场景仅 `console.error`，不阻断流程。

## 4. 约定与约束

- **资源加载失败必须提供降级视图**：`ImageWithFallback` 将 `onError` 事件转换为占位图显示，避免空白图片破坏布局。
- **Context 相关 Hook 必须在 Provider 内使用**：`useLaunchNotice`、`useCarousel`、`useChart`、`useSidebar` 等均在 context 缺失时抛错，这是对这些 Hook 使用方式的硬性约束。
- **表单错误信息通过 form 上下文传递**：`form.tsx` 中 `FormMessage` 从 `useFormField()` 获取 `error.message` 并渲染，组件需遵循此约定才能显示错误。
- **用户输入校验优先于网络请求**：`Login.tsx` 在校验手机号格式后直接返回，不发起后续逻辑。
- **无全局错误边界**：未发现 `React.ErrorBoundary` 或全局 `window.onerror` 拦截器，错误处理粒度停留在单个组件/页面级别。
- **无服务端错误处理**：由于是纯静态站点，不存在 HTTP 错误码、中间件或 API 响应错误转换逻辑。
